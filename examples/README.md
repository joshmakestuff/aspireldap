# Examples

A runnable, end-to-end sample for the AspireLdap integrations.

## What it shows

An Aspire **AppHost** runs an OpenLDAP container (seeded with two hand-declared users, a group, and 25 generated fake people in 4 fake groups) plus the bundled **LdapAdmin** interface, and a minimal **Web API** consumes the directory through the **instrumented [`OpenLdapClient`](../aspireOpenLdap/Aspire.OpenLdap/README.md#telemetry)**.

The example consumes the published `0.9.0-preview.1` hosting and client packages. The hosting package supplies the LdapAdmin app and Dockerfile; both the OpenLDAP and LdapAdmin images are built locally on first run.

It demonstrates:

- **Hosting** — `AddOpenLdap("openldap")` with seed data (`WithUser`/`WithGroup`/`WithOrganizationalUnit`) in the AppHost.
- **LdapAdmin** — `WithLdapAdmin()` adds a development-time UI for browsing, searching, and editing the directory, managing memberships, inspecting schema, and importing/exporting LDIF.
- **Fake data** — `WithFakeDirectory(seed: ...)` seeds deterministic (fixed-seed) `inetOrgPerson`/`groupOfNames` entries, generated by the bundled [`LdifDotNet.Generator`](https://www.nuget.org/packages/LdifDotNet.Generator).
- **Client** — `AddOpenLdapClient("openldap")` in the API, resolving `OpenLdapClient` and calling `Send(...)`.
- **Client OpenTelemetry** — every LDAP operation emits an `LDAP search` span (nested under the incoming HTTP request span) and a `db.client.operation.duration` metric on the `Aspire.OpenLdap` source/meter, all visible in the Aspire dashboard.

## Run it

Requires the .NET 10 SDK, the Aspire 17 CLI bundle, and Docker. The AppHost uses `Microsoft.NET.Sdk` with `Aspire.Hosting.AppHost` and registers the API by path with `AddDotnetProject` from `Aspire.Hosting.Dotnet`. The first run restores the packages and builds the container images.

```sh
aspire run --apphost examples/AspireOpenLdap.AppHost/AspireOpenLdap.AppHost.csproj
```

Then:

1. Open the **dashboard** (the URL is printed on start).
2. Open the **`openldap-ldapadmin`** resource's HTTP endpoint. LdapAdmin opens directly onto the directory using the AppHost-provided credentials; no login is required. Expand `ou=people` to inspect Alice, Bob, and the generated entries. This interface is intended for local development.
3. Call the API's **`GET /users`** endpoint — find its URL on the dashboard's **Resources** page. Before any directory edits, it returns the 27 seeded users (alice, bob, and the 25 generated people).
4. In the dashboard, open **Traces** → each `GET /users` trace contains a nested `LDAP search` span. Open **Metrics** → the `api` resource → `db.client.operation.duration`.

## Projects

| Project | Role |
| --- | --- |
| `AspireOpenLdap.AppHost` | Aspire AppHost — runs OpenLDAP, the API, and LdapAdmin |
| `AspireOpenLdap.Api` | Minimal Web API that queries the directory via `OpenLdapClient` |
| `AspireOpenLdap.ServiceDefaults` | Standard Aspire service defaults (OpenTelemetry export, health checks) |

> **Linux note:** the client uses `System.DirectoryServices.Protocols`, which needs the native `libldap` library installed at runtime (any of the 2.4/2.5/2.6 sonames — `AddOpenLdapClient` resolves whichever your distro ships automatically). See [Requirements on Linux](../aspireOpenLdap/Aspire.OpenLdap/README.md#requirements-on-linux).
